## 1. Executive Summary

This specification defines the architecture for Projectionist’s deterministic, zero-latency metadata taxonomy engine and its associated background maintenance loop.

To satisfy homelab resource boundaries, eliminate external API dependencies, and prevent search rail regressions, the runtime resolution pipeline operates on an in-memory local taxonomy dataset using strict, fail-closed matching.

To maintain taxonomy freshness over time without runtime performance penalties, an asynchronous background task aggregates unmapped search tokens, cross-references them against stored TMDB keyword graphs, and stages candidate alias mappings for administrative promotion.

---

## 2. Core Architectural Principles

1. **Zero-Latency Query Path:** Search, gaps, and motif expansion lookups resolve via in-memory dictionary trees and local SQLite indexes. No external LLMs, network services, or cloud classifiers are invoked during live requests.
2. **Fail-Closed Resolution:** Unrecognized or ambiguous genre/motif tokens return empty ID sets and candidate suggestions. Unresolved strings are never injected as raw sentence queries into external search APIs.
3. **Decoupled Observation:** Query misses write to an isolated SQLite telemetry buffer asynchronously via `asyncio.to_thread`. Missing a token never blocks or delays a user response.
4. **Automated Discovery, Human Curation:** High-frequency unmapped terms are discovered and clustered automatically by a scheduled background process, but non-exact or ambiguous alias additions require explicit owner promotion.

### B. Unmapped Telemetry Buffer (`unmapped_facet_telemetry` Table)

A lightweight table inside `projectionist.db` logs unresolved search terms without cluttering the primary library database.

```sql
CREATE TABLE IF NOT EXISTS unmapped_facet_telemetry (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    raw_token TEXT NOT NULL,
    context_source TEXT NOT NULL,
    media_type TEXT NOT NULL,
    hit_count INTEGER DEFAULT 1,
    first_seen_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_seen_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_unmapped_token UNIQUE (raw_token, context_source, media_type)
);

CREATE INDEX IF NOT EXISTS idx_unmapped_hit_count ON unmapped_facet_telemetry(hit_count DESC);

```

## 4. Runtime Resolution Engine

### Resolution Pipeline

```
Inbound Query Token
       |
       v
Normalized String (Lower / Strip Punctuation)
       |
       +---> Exact Match in Local Taxonomy Aliases?
       |        |
       |        +--> YES: Return Canonical TMDB Genre IDs + Keyword Unions
       |        |
       |        +--> NO: Fail Closed
       |                |
       |                +--> Return Empty Set / Candidate List
       |                |
       |                +--> Async Fire-and-Forget Write to unmapped_facet_telemetry

```

### Unmapped Token Logging Contract

When `resolve_genre_ids` encounters an unmapped term:

1. Returns an empty ID list (`[]`) to prevent bad API parameter passes.
2. Invokes an asynchronous worker:

```python
async def log_unmapped_token(raw_token: str, context_source: str, media_type: str) -> None:
    query = """
    INSERT INTO unmapped_facet_telemetry (raw_token, context_source, media_type, hit_count, last_seen_at)
    VALUES (:token, :source, :media_type, 1, CURRENT_TIMESTAMP)
    ON CONFLICT(raw_token, context_source, media_type) DO UPDATE SET
        hit_count = hit_count + 1,
        last_seen_at = CURRENT_TIMESTAMP;
    """
    await asyncio.to_thread(db_execute, query, {"token": raw_token.strip().lower(), "source": context_source, "media_type": media_type})

```

## 5. Background Maintenance Task Architecture

### Task Identity

* **Name:** `facet_taxonomy_audit`
* **Module:** `projectionist/scheduler/tasks/facet_taxonomy_audit.py`
* **Trigger:** Scheduled weekly during system idle window or manually executed via the Admin Settings UI.

### Task Execution Steps

1. **Threshold Filtering:** Read `unmapped_facet_telemetry` for tokens where `hit_count >= 5`.
2. **Library Graph Analysis:** Scan local database items to see if the unmapped token appears frequently in local TMDB keyword strings or tags across owned items.
3. **TMDB Master Cross-Check:** Query local TMDB cached keyword registries to verify if the unmapped token matches a recognized TMDB keyword ID.
4. **Candidate Generation:**
* If a token matches an existing TMDB Keyword ID and appears in $\ge 10$ owned library titles, calculate a confidence score $\ge 0.80$.
* Write candidate metadata to `data/taxonomy_candidates.json`.


5. **Telemetry Pruning:** Purge entries from `unmapped_facet_telemetry` that are older than 30 days and have fewer than 3 hits.

## 6. Promotion Workflow

```
                        +----------------------------+
                        | Candidates JSON Generated  |
                        +----------------------------+
                                      |
                         Confidence Score >= 0.95?
                                      |
                     +----------------+----------------+
                     |                                 |
                 [ YES ]                            [ NO ]
                     |                                 |
                     v                                 v
        Auto-Merge Candidate               Stage Card in Admin UI
    into Active Taxonomy JSON             (Approve / Reject Action)
                     |                                 |
                     +----------------+----------------+
                                      |
                                      v
                        Update Active Runtime Index

```

### Auto-Promotion Policy

High-confidence additions (exact string matches for official TMDB keyword IDs with high local library density) automatically merge into the active runtime taxonomy during the audit task run.

### Manual Override & Overlay (`PROJECTIONIST_FACET_ALIASES`)

Owner-approved terms from the Admin UI are written to `DATA_DIR/facet_aliases_override.json`. The runtime loader reads `taxonomy.json` first and merges `facet_aliases_override.json` on top at application boot, preserving custom user edits across container upgrades.

## 7. Verification Gates & Acceptance Criteria

| Area | Assertion Criteria |
| --- | --- |
| **Latency** | Runtime alias resolution completes in $< 1\text{ms}$; unmapped telemetry logging adds $0\text{ms}$ blocking time to the query path. |
| **Fail-Closed Safety** | Searching for unknown or complex natural language phrases never injects raw sentences into `search_tv` or `search_movie` API calls. |
| **Audit Execution** | `facet_taxonomy_audit` runs to completion without errors, populating `taxonomy_candidates.json` and cleaning expired telemetry entries. |
| **Persistence** | Custom mappings saved via the Admin UI persist across container restarts inside the `DATA_DIR` overlay file. |
