## Step 2: Purge the reviews from history (confirm with the person first)

Untracking does not remove what is already on GitHub: every commit since the reviews were added still contains them, including security findings. A full purge rewrites history. It is safe only because no PRs are open, but it is **disruptive and hard to undo**. **Ask the person for an explicit “yes, rewrite history” before running the force-push.** Prepare everything up to that point.

```bash
# 1. Full backup (keep it until the person says otherwise)
cd ~/code && git clone --mirror git@github.com:romwil/projectionist.git projectionist-backup-$(date +%Y%m%d).git

# 2. Rewrite in a fresh mirror clone, not the working checkout
git clone --mirror git@github.com:romwil/projectionist.git projectionist-purge.git
cd projectionist-purge.git
git filter-repo --path docs/reviews --invert-paths      # brew install git-filter-repo

# 3. Verify nothing remains
git log --all --oneline -- docs/reviews | wc -l          # must be 0
git rev-list --all | xargs -n1 git ls-tree -r --name-only 2>/dev/null | grep -c '^docs/reviews/'   # must be 0

# 4. STOP. Report counts, and ask the person to confirm.
# 5. Only after a yes:
git push --force --mirror
```

Then:

- Re-sync the working checkout: `cd ~/code/projectionist && git fetch --all && git checkout main && git reset --hard origin/main` (local-only files in `docs/reviews/` and `.cursor/review/` are ignored and survive; confirm with `ls docs/reviews | head`).
