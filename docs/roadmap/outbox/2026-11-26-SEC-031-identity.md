# Platform handoff: household sign-in methods and linked accounts

**Date:** 2026-11-26 · **Server items:** SEC-028, SEC-029, SEC-030, SEC-031, SEC-032, SEC-033, SEC-034 · **Client item waiting:** APL-064

## What the platform will offer

Passkeys are built with `py_webauthn`, and TOTP with `pyotp`, inside an isolated identity module. There is no companion container. Generic OIDC stays. The Plex-token sign-in route goes away (SEC-028).

*Proposed* capabilities, each `1` when that item has shipped and absent until then:

- `passkeys` with SEC-031
- `linked_accounts` with SEC-029

Anonymous `GET /api/features` already returns sign-in methods (SEC-022). After SEC-034 it lists only methods the owner has enabled. When Plex sign-in is off, the list does not mention Plex.

Native clients still finish every method in the system web-auth sheet and receive a device credential (NAT-002). That contract does not change.

Linked accounts are not a sign-in. The record can hold a Plex server user id, a plex.tv account id when known, a Seerr user id, and later a Jellyfin user id (ENG-010). Revoking a link deletes the stored token.

## Order

SEC-028, then SEC-029, then SEC-030. The app door (SEC-036) comes before SEC-031. Then SEC-032, SEC-033, and SEC-034. Each identity pull request waits for an explicit approval comment before it merges.

## Done when the client cares

- A passkey sign-in and a password sign-in each return a device credential.
- With Plex sign-in off, no sign-in surface mentions Plex.
- Settings can show the links the server reports, including when the member's own Plex token is not connected.

Do not build the client until the passkeys module and the methods list have merged.
