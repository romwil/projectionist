# Handoff: prepare the film while the preroll plays

**Server item:** ENG-015
**Status:** server session is in. Not a release. Clients wait for a server that serves the capability.
**Capability:** `preroll_warm_start` is `1` on `GET /api/features`. A missing name means the client keeps today's order: play the preroll, then open the film session.

This handoff is the platform contract. Client screens and layouts stay in the client repository.

## Routes

No new route.

- `POST /api/playback/sessions` still opens the film session. Send `preroll: true` when a bumper will play. The server prepares that session at the resume point while the preroll runs. The rest of the body is unchanged, including `engine_opt_in` when the client is opting into the engine.
- A library plan uses the library session the client already opens. The server starts that preparation at Play as well. If the engine stops during the preroll, the same session read moves to plan `library`, starts that transcode, and includes `library_session_id` and `stream_url`.
- `GET /api/playback/sessions/{session_id}` is the existing read. Additive fields: `state` (`preparing`, `ready`, `failed`), `prepare_ms`, and `ready_at_handoff`. `?handoff=true` records the hand-off once.
- `POST /api/playback/sessions/{session_id}/stop` stops the preparation, including a library transcode this session started. Back during the preroll uses it.

The `preparing` / `ready` / `failed` states belong to the session-state work already underway. ENG-015 reports them during the preroll. It does not define them.

## What the client does

- Request the film session when the preroll starts, not after it ends.
- Preload the film playlist and the first segments during the last few seconds of the preroll, and switch with no gap when `state` is `ready`.
- If the film is not ready when the preroll ends, leave the warm-up screen up (EXP-018) with the session's real step.
- Start the first-frame fallback clock at that hand-off. If the server already moved to the library plan during the preroll, play the session it returned.
- Back during the preroll stops the film session and the preroll. The server must leave no encoder and no library transcode running.

## Done when the client ships

With prerolls on, a film goes from preroll to picture with no visible gap. Back during the preroll leaves no session running on the server.

## Depends on

ENG-003. The session states from the work already running. EXP-018 only for the gap when the film is not ready at hand-off.
