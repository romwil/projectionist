# Outbox handoff — NAT-005 device kind (Apple clients)

**To:** Projectionist.iOS / Apple client agents  
**From:** Projectionist server roadmap (2026-11-19)  
**Server item:** NAT-005  
**Waiting client item:** APL-016  
**Capability:** *Proposed:* bump when `kind` appears on pair claim / list responses (ship behind NAT-001 once that lands; until then treat as additive JSON fields on existing pairing routes)

## What the server will do

- Store `kind` on the device record: `tv` | `iphone` | `ipad` (exact enum *proposed*).
- Accept kind on claim (and optionally on issue) so the Settings claim page and device list can speak the right device — not always “Apple TV”.
- Rename member Settings chrome from **Apple TV** to **Devices** when kinds beyond TV exist.
- Does **not** require NAT-002 (native sign-in); existing pair code flow is enough for handhelds.

## Routes (existing; fields *proposed*)

| Method | Path | Change |
|--------|------|--------|
| `POST` | `/api/devices/pair/claim` | Request may include `kind`; response includes `kind` |
| `GET` | `/api/devices` (or current list route) | Each device includes `kind` |
| issue / rotate / pending | unchanged contract | May echo requested kind on pending if issued with one |

Exact OpenAPI / fixtures land with NAT-003 / NAT-004 when those ship. Do not invent additional routes in the client.

## What the client must do (APL-016)

- Send `kind` on claim from the platform that is pairing.
- Render list / empty / confirmation copy from `kind`, not a hard-coded “Apple TV” string.
- Keep proprietary UI details out of the public server repo.

## Done when (needs client)

- A member can pair an iPhone and see it listed as a phone, not a television.
- Claim confirmation matches the device in hand.
- TV pairing still works with `kind=tv`.
