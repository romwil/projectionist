# Handoff: session object

**Date:** 2026-11-21 · **Server item:** SES-003 · **Capability:** `session_object` 1

## What changed

`POST /api/sessions` starts a session on a room:

```json
{
  "id": "…",
  "owner_id": "…",
  "screen_id": "…",
  "rating_key": "123",
  "position_ms": 0,
  "state": "playing",
  "level": "off",
  "engine_session_id": "",
  "youth": false,
  "updated_at": 0
}
```

`level` is `off`, `moments`, `popups`, or `class`. `state` is `playing`, `paused`, `buffering`, or `ended`.

The starter may `PATCH` the level and `DELETE` the session. The member signed in on the screen may `GET` it and `PATCH` `position_ms` and `state`. Anyone else receives 404 and learns nothing about the title. One session per screen; a new one ends the previous one.

`shared_sessions` stays 0. This object is not the realtime channel.

## What the client does

- Open a session when `session_object` is at least 1, on a room id from `GET /api/rooms`.
- The screen reports position. The starter sets the level.
- Do not show the session to a member who receives 404.

## Done when (client)

- The screen and the starter see the same owner, screen, position, and level.
- Another signed-in member is not shown that session.
