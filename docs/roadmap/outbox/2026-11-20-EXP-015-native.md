# Outbox handoff — EXP-015 weather headline flags

**To:** native client agents  
**From:** Projectionist server roadmap (2026-11-20)  
**Server items:** EXP-015 (flags), EXP-014 (web presentation only; native presentation is the client’s)  
**Capability:** none new. The weather payload gains fields. Treat a missing `enabled` as today’s behavior until the server ships EXP-015.

## What the server will do

Headline groups already arrive by scope (local, national, world), four each, titles as published, with source. EXP-015 adds:

- `headlines.enabled` — false when this viewer should not see headlines (owner setting off, or a Youth session whose owner has not allowed them).
- per-scope `available` — the client renders nothing for a scope that is not available.
- When headlines are off for that viewer, the server does not fetch a news feed for them.

Titles are never rewritten.

## What the client must do

- If `enabled` is false, show no headlines.
- Render each title as published, with its source. Do not summarize.
- Radar and the other boards keep using the payload the server already sends (`boards.radar.frames[]`, current conditions, almanac). No new route.

## Done when (needs the client)

- A Youth session shows no headlines unless the owner has allowed them.
- Turning headlines off on the server removes them from the channel without a client release beyond reading `enabled`.

## Addendum (2026-11-20, evening)

The person decided the same day:

- Weather boards show UV index and air quality. The payload already carries them on the air facts (`uv_index`, `uv_label`, `aqi`, `aqi_label`), from `air-quality-api.open-meteo.com`. That host is already in PRIVACY.md. It is not a new egress host. A missing reading stays blank.
- Local headlines stay a Google News search for the place. EXP-015 does not add another source.
- Owner RSS feeds are later (EXP-017, proposed) and are not part of EXP-015. Do not fetch them.
