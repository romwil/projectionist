# Outbox handoff — NAT-002 native sign-in

**To:** native client agents  
**From:** Projectionist server roadmap (2026-11-20)  
**Server item:** NAT-002 (same work as SES-001)  
**Capability:** `native_sign_in` is `0` on `GET /api/features` until the paths below ship, then `1` (NAT-001). A public list of enabled methods (Plex, local, OIDC, and whether access requests are open) ships with the `1`.

## What the server will do

Every current web sign-in path can return a device credential instead of setting `curatorx_session`, when the request includes a native client. *Proposed* body field: `client: {"kind": "iphone" | "ipad", "label": "…"}`. The credential is returned once. The device is stored like a paired TV (hashed credential, listed and revocable). The pair-code flow stays available as a secondary path.

| Path | Native need |
|------|-------------|
| Plex | Same PIN flow. The final step returns a device credential. The PIN nonce is client-held in the body, not a cookie |
| Local | Login and register return a device credential |
| OIDC | Allowlisted custom-scheme redirect and PKCE. The callback carries a short-lived single-use code. The app exchanges that code for the credential. The credential is never in a URL |
| Invite | `GET /api/invites/validate` stays public and returns only the inviter display name, role, and expiry. Redeem paths return a device credential. The web Join page gains an open-in-app link with the server base URL and the invite token |
| Request access | Usable without a cookie, same as today |

## What the client must do

- Send `kind` and a label, and store the credential in the device keychain.
- Use the system web-auth sheet for Plex and OIDC. OIDC uses PKCE and the allowlisted redirect.
- Register the custom scheme for the auth callback and for invite links. Also accept a pasted invite link.
- Show only methods the public list says are enabled.
- Do not put a credential in a URL or a log.

Exact request and response JSON lands with NAT-003 / NAT-004. Do not invent fields beyond this note.

## Done when (needs the client)

- A new member can redeem an invite with each enabled method and land signed in, with the device listed under Settings → Devices.
- An existing member can sign in with Plex, a local password, or single sign-on.
- No credential appears in a URL.
