# Outbox handoff — NAT-006 content-free push and approvals

**To:** native client agents  
**From:** Projectionist server roadmap (2026-11-20)  
**Server item:** NAT-006  
**Depends on:** NAT-002. Youth join approval is SES-009. Edition-ready is TRK-008. Device kind is NAT-005.  
**Capabilities:** `push` and `approvals` are `0` until this ships, then `1` (NAT-001).

## What the server will do

- Store an APNs token on the device record. Revoking the device drops the token. A self-hosted server sends through the publisher relay.
- Every push is content-free: `approval_needed`, `something_ready`, or `security_notice`, plus an opaque id. No title, member name, device name, or library data goes to the relay.
- An approval object a signed-in device can approve or deny. It covers a pair-code sign-in (the code path stays the fallback; *proposed:* the issuing device names the member first) and a Youth join (SES-009). Approvals expire, are single-use, are audited, and the server re-checks authorization when one is acted on.
- When an account gains a device by any NAT-002 path, the member’s other devices get `security_notice`.
- Per-member preferences for which kinds they receive.
- If the relay is down, the same approvals still work in the app and on the web.

## What the client must do

- Register for push and send the token with the device credential.
- On a push, fetch the detail from the household server. Do not render title, name, or device text from the payload.
- Approve and Deny re-check with the server before acting.
- Offer the same approvals inside the app when push is unavailable.

## Done when (needs the client)

- A phone can approve a new device’s pair code without typing it on the web, and Deny leaves the code path working.
- A new device produces a notice the member can open to review or remove that device.
- A Youth join can be approved from the notification and from inside the app.
- An edition-ready push (TRK-008) opens the item after the app fetches it.
