# Handoff: joining a session

**Date:** 2026-11-23 · **Server item:** SES-005 · **Capability:** `session_join` 1

Depends on `shared_sessions` 1.

## What changed

`POST /api/rooms/{id}/join` joins the session on that screen. The code from `GET /api/sessions/{id}/code` joins immediately. The starter, and the member signed in on the screen, can read the code. A guest cannot.

With no code, the response is `pending` and a `request_id`. It does not include the title. The starter lists requests and posts `approve` or `not_now`. Not now stays declined for the rest of that session, still without the title.

Guests can read the session. They can pause, seek, skip, and play at double speed only when `guests_may_remote` is true. They cannot change the level, the room's captions, report position on the session object, or end the session.

A wrong code is refused. After several wrong codes the route asks the member to wait.

## What the client does

- Join when `session_join` is at least 1.
- Show the code only on the screen that is playing, and to the starter.
- Treat `pending` and `declined` as sentences with no title.
- Send transport only when `guests_may_remote` is true.

## Done when (client)

- A member with the code can read the session.
- A member without it cannot see the title until the starter approves.
